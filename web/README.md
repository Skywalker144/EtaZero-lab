# EtaZero 开发工作台

在仓库根目录运行：

```bash
bash web/webui.sh
```

脚本使用 Conda `pytorch`，按版本号各段数值选择最新的 `EtaZero_V*` 主线目录，在 <http://127.0.0.1:8766> 提供单用户工作台并自动打开浏览器。启动时执行 CMake 增量构建，由构建系统检查原生依赖并复用未变更的产物。`--rebuild` 强制执行构建，用于更改工具链或构建选项后；`--no-open` 禁用自动打开。已经处于 `pytorch` 环境时直接启动，否则只进入一次 Conda 环境。

默认递归扫描该版本整个 `data/`，发现包含 `config/effective.json` 或 `models/` 的运行目录，包括实验伞目录下的嵌套运行。先选择“配置目录”，再选择“权重代数”；代数对应训练 iteration，按数值倒序排列，默认选择 `models/current.json` 指向的当前发布权重，没有发布指针时选择最新一代。尚未发布权重的目录显示“暂无权重”，不能创建棋局。存在可用的 `checks/minimal_test` 时默认选中它，否则选择首个有权重的目录；`--model` 可指定初始选择。

支持 AlphaZero 和 MuZero 已发布模型；V3 的围棋与中国象棋通过模型 manifest 的棋类布局选择。围棋可设规则／贴目并停一手；象棋显示九路十行和中文棋子，先选起点再选合法终点，可从 FEN 开始。象棋手动走子、AI 应手和单步回看／撤回时，棋子平滑移到落点，吃子在到达时淡出；人机连续走子按顺序播放，合并收到的更新也逐手显示，播放期间不能在棋盘上走下一手。重开与跨多手回看跳转直接显示目标局面，遵循系统“减少动态效果”设置。历史回看、悔棋和继续分支使用 native 保存的实际棋盘，保留提子与移子结果。象棋策略以起终点动作列表显示，原始网络面板可按起点查看全部 2086 动作，不能把它们当成格点概率。

支持 AlphaZero 和 MuZero 已发布模型。运行路径相对于 `data/` 映射到同版本 `configs/`，加载对应 `analysis.cfg` 的显式引用、公共 `engine.cfg`、本机与 `ENGINE_*` / `ANALYSIS_*` 覆盖；找不到对应配置时，按模型算法使用 `baseline` 或 `mz_g` 评估配置，默认棋盘尺寸取模型画布或保存的配置。`--config-dir` 可统一覆盖评估配置，须满足所选模型的搜索约束。MuZero 使用原生 latent 搜索，评估配置要求关闭图搜索和树复用、根对称数为 1。

点击“创建棋局”加载模型；“刷新模型”重新扫描目录和权重，无需重启服务，保留当前选择、棋局和已加载模型。切换配置目录会填入该目录的默认棋盘、棋规和预算，围棋同时填入规则与贴目，新模型与评估配置在重开棋局后生效。刷新页面时恢复当前围棋棋局的规则与贴目；生效配置面板显示实际棋局参数。围棋和象棋不读取五子棋／Hex 的平衡开局配置，也不要求提供 `match.cfg`。

Hex 使用六角格棋盘，黑方连接上下边、白方连接左右边；按实际六邻接路径连通判胜。创建棋局时可选择“空盘”或“平衡开局”。平衡开局复用当前棋类的比赛开局算法：五子棋由所选模型评估双方视角，Hex 用白方胜率拒绝采样黑方首手。参数读取对应配置目录 `match.cfg` 的 `[opening]` / `[hex_opening]`、显式引用、叶子 `.local` 和 `MATCH_OPENING_*` / `MATCH_HEX_OPENING_*` 覆盖；正常对弈仍使用 `analysis.cfg`。每次生成使用新种子，棋盘下方显示开局手数、尝试次数、网络 W−L 与生成耗时，种子及完整参数可在“平衡开局”面板查看。W−L 标注最后一手平衡着后的行棋方视角，可能与可选 policy init 后的行棋方不同；模型估值接近零不保证真实胜率为 50%。

`max_tries` 是降低拒绝概率的阈值，超过后继续尝试直到成功或取消。生成在模型响应超时前取消，失败或取消明确报错，不发布部分开局。成功生成后按实际行棋方决定 AI 是否应手，局面研究模式不自动应手。

## 会话与局面研究

桌面采用配置、棋盘、分析三栏，左右侧栏等宽，棋盘水平居中。窄屏将配置区折叠到顶部，棋盘与分析上下排列。界面采用中性灰白和黑白高对比主按钮，主题默认跟随系统配色并随系统设置实时变化，右上角可选择“跟随系统 / 浅色 / 深色”；主题与手数偏好保存在浏览器，热力图随主题调整配色。支持手数显示、键盘操作和窄屏布局。配置区分为“模型与棋局”和“会话控制”，通过目录和代数两个下拉框选择模型，并查看 manifest、权重路径、SWA 信息与生效搜索配置。

- **人机对弈**：选择执子方，AI 自动应手；空盘且人类执白时 AI 先行。“撤回”退至最近一次人类落子前，保留生成的开局前缀和人类首次落子前的 AI 应手。
- **局面研究**：手动交替落黑白棋，“开启分析”持续搜索当前方但不落子，“AI 单步”仅让当前方落一手。“撤回”只退一手。仍执行真实棋规，包括 Renju 黑棋禁手判负。
- **持续分析**：默认暂停，点击“开启分析”后持续推送结果，不受 AI 落子访问上限限制。分析期间可落子、撤回、AI 单步或从历史继续；先停止旧搜索，操作完成后自动分析新局面。点击“暂停分析”后一直保持暂停，落子、撤回、重开或切换模式均不会自行开启；再次点击才恢复。分析开关由服务端保存，刷新网页保留。终局停止搜索，开启状态下撤回到非终局会继续分析。
- **会话配置**：模型、尺寸、棋规和开局类型需重开棋局生效；模式、执子和预算可点击“应用模式 / 执子 / 预算”更新而不重开。未应用的改动会显示提示。切换模式或执子不会自动落子；若轮到 AI，可点击“重试 AI”或“AI 单步”。
- **历史回看**：点击落子记录、拖动滑块或使用左右键。回看为只读，不改变服务端棋局。“当前”返回最新局面；“从此处继续”撤回后续落子、清除旧分析并进入手动研究模式，不保留被撤回的变化。

生成的开局动作计入完整历史。手动研究的撤回及“从此处继续”允许回到开局前缀内部；修改前缀后清除原开局估值与元信息。

快捷键：`A` 开启 / 暂停分析，`Esc` 暂停正在进行的持续分析，`S` AI 单步，`U` 撤回，`←` / `→` 回看，`Home` 初始局面，`End` 当前局面。编辑表单时不触发普通全局快捷键，`Esc` 仍可暂停分析。

棋局由服务保存，刷新网页可继续；关闭服务后不保留。多个标签页共享同一个棋局，通过状态版本拒绝过期操作；同一局面的分析快照不使操作失效。AI 落子搜索 / 加载期间锁定修改，仍可回看历史；点击“停止搜索”取消后保留棋盘、关闭持续分析，AI 不执行部分结果的落子。请求失败显示错误，搜索失败暂停分析，连接中断后自动重连。模型进程退出或超时后重开棋局重新加载。

## 搜索分析

分析面板明确显示搜索前的手数与执子方，区分当前局面和历史分析。“定位局面”将主棋盘切到该搜索对应的局面。持续分析定时推送候选快照，暂停后保留停止时的结果。新局面的首个快照到达前可保留上次完整分析，并标注正在更新；局面不匹配时不在棋盘叠加。撤回、从历史局面继续或重开清除旧分析。持续分析关闭时，AI 落子后保留该步落子前的结果；开启时自动转到落子后的局面。

- 显示实际根访问数、搜索耗时、根访问 / 秒、搜索 W−L、搜索与网络 W/D/L，以及 NN 请求数、推理批次数和平均批量。所有价值均为标注的搜索方视角，W−L 不等同于胜率。
- 主棋盘“候选分析”大字显示和棋计半分的得分率，小字显示访问数，角标是选点排名；颜色按相对访问量变化，文字与角标采用独立的深浅主题配色。窄棋盘隐藏访问小字以保持可读字号，完整访问数见候选表或悬停详情。先按访问数取 Top-K 并过滤低访问占比，再按 PUCT 选择权重或 Gumbel 改进策略排名。悬停查看 W/D/L、效用、LCB、置信半径和合法主变化，支持五子棋与 Hex。
- 候选表包含全部合法点的网络先验、原始访问数、访问占比、选择权重、得分率、和棋率、LCB、原始权重与改进策略；可选择仅显示棋盘候选，排名与棋盘一致；支持点击表头排序、仅看已访问点、点击点位在棋盘定位。概率列背景条表示实际百分比。候选行与热力图在悬停或键盘聚焦时预览主棋盘点位，仅在当前展示局面与分析匹配时生效；点击点位可定位到对应的搜索前局面。星号表示本次搜索选出的建议点，不保证是先验或选择权重最大值（落子含配置温度）。
- 策略对照显示同一搜索前局面的网络先验与访问分布 / 选择权重；主棋盘也可叠加这些数值。棋盘与分析不匹配时不叠加，并显示提示，避免将旧分布画在新局面上。
- 候选得分率为 `P(胜)+0.5×P(和)`，来自纯 W−L，不能使用带 SubtreeValueBias 的效用代替概率。LCB 和半径使用搜索实际效用尺度；未访问点的价值为空，关闭 LCB 或 Gumbel 时 LCB 显示“—”。Gumbel 的选择分布在搜索结束后才确定，按改进策略为各候选排名。
- 网络先验在合法点归一化，包含全树 NN policy 温度，不含根温度 / 噪声；原始访问分布由 child visits 归一化，选择权重来自目标剪枝与 LCB。各图颜色分别按最大值线性缩放，数值为实际百分比。
- **网络输出**：并排展示普通策略、对手策略、长期 optimistic 和短期 optimistic 四个头，支持概率 / 原始 logits 和统一 / 独立色阶，悬停显示精确值，点击定位局面；每图显示最高概率点、分布熵（nats）与已落子位置的概率质量。两个 soft 头不展示。对手策略从当前局面预测对手下一手，不交换执子；optimistic 是训练加权策略，不是逐点胜率。
- 四头来自搜索前局面的额外一次固定朝向推理，复用常驻模型和生效推理精度；持续分析在启动搜索前提取并随首个快照显示，局面改变后重新提取，无需等待暂停。不使用搜索温度、optimism 混合、噪声或对称集成。概率采用温度 1、在整个有效棋盘归一化（包含已落子位置，排除 padding），与合法点上的搜索先验口径不同。此诊断推理不计入搜索耗时与 NN 请求 / 批次，响应延迟包含它；AlphaZero 与 MuZero 均展示真实棋盘根局面的输出，不展示 latent 搜索子局面。
- “原始数据”提供最近一次分析的只读 JSON，便于核对原生返回值。

模型在 C++ 进程中常驻，同一模型与评估配置重开复用进程。加载时检查输入契约和文件大小；只读取已发布的 TorchScript 推理模型（包括发布时选用的 SWA），不读取训练 checkpoint。棋规与搜索使用目标版本原生实现，每次搜索从新根开始。AI 落子的根访问上限最少为 2，包含一次初始根评估，并受评估配置其他停止条件约束；持续分析使用原生 continuous 请求，覆盖访问、playout 和时间上限，直到暂停或改变局面。程序按指定设备运行，不自动回退到 CPU。

```bash
# 指定模型：同目录必须包含 manifest.json。
bash web/webui.sh --model "EtaZero_V1/data/<运行目录>/models/<模型目录>/model.pt"
# 限定扫描到目标版本中的某个运行或实验伞目录。
bash web/webui.sh --models-dir "EtaZero_V1/data/<运行目录>" --port 8766
# 独立评估配置，支持 ANALYSIS_* 环境覆盖。
ANALYSIS_SEARCH_THREADS=8 ANALYSIS_DEVICE=cuda:0 bash web/webui.sh
```

实现入口：[server.py](server.py)、[app.py](app.py)、[engine.py](engine.py)、[原生共享会话](../EtaZero_V2.7/cpp/src/commands/session.cpp)、[GTP / JSON 协议](../EtaZero_V2.7/docs/engine.md)、[界面](static/)。启动参数以 `python -m web.server --help` 为准。

## 验证

真实 CUDA 模型检查，在仓库根目录执行：

```bash
PYTHONPATH=EtaZero_V2.7/python:. \
ETAZERO_WEB_TEST_MODEL="$PWD/EtaZero_V2.7/data/<运行目录>/models/<模型目录>/model.pt" \
conda run --no-capture-output -n pytorch python -m unittest discover -s web/tests -p test_web.py -v
```

不设置 `ETAZERO_WEB_TEST_MODEL` 时仍运行目录发现、代数排序、空目录、刷新和配置路由测试；真实模型测试支持 AlphaZero 或 MuZero，根据 manifest 自动选择评估配置。

浏览器检查需要已有 Playwright 和 Chromium，会重开、回退并完成棋局，应对独立测试服务执行：

```bash
bash web/webui.sh --port 8767
ETAZERO_WEB_TEST_URL=http://127.0.0.1:8767 \
conda run --no-capture-output -n pytorch python -m unittest discover -s web/tests -p test_browser.py -v
```
